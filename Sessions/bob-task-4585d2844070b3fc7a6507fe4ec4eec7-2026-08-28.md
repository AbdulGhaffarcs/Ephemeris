### Proposed refactoring (three independent improvements)

#### ① Vectorise the per-point calculations

**What changes**  
Replace the entire `for i in range(n)` loop with broadcasting over the `(n, 3)` arrays already in memory.

```python
# sun_hat[i] = sun_gcrs_km[i] / ||sun_gcrs_km[i]||
sun_norms  = np.linalg.norm(sun_gcrs_km, axis=1, keepdims=True)   # (n,1)
sun_hat    = sun_gcrs_km / sun_norms                               # (n,3)

# proj[i] = dot(sat_pos[i], sun_hat[i])
proj       = np.einsum("ij,ij->i", pos_km, sun_hat)               # (n,)
perp_sq    = np.einsum("ij,ij->i", pos_km, pos_km) - proj**2      # (n,)
in_eclipse = (proj < 0.0) & (perp_sq < EARTH_RADIUS_KM**2)        # (n,) bool

# z_hat[i] = -sat_pos[i] / ||sat_pos[i]||
pos_norms  = np.linalg.norm(pos_km, axis=1, keepdims=True)         # (n,1)
z_hat      = -pos_km / pos_norms                                    # (n,3)

sat_to_sun = sun_gcrs_km - pos_km                                   # (n,3)
sts_norms  = np.linalg.norm(sat_to_sun, axis=1, keepdims=True)     # (n,1)
sts_hat    = sat_to_sun / sts_norms                                 # (n,3)

cos_angles = np.clip(np.einsum("ij,ij->i", z_hat, sts_hat), -1.0, 1.0)
sun_angles = np.degrees(np.arccos(cos_angles))                      # (n,)

elapsed    = np.arange(n) * step_s                                  # (n,) int
phases     = (elapsed % period_s) / period_s                        # (n,)
```

Then build `out` with a single list comprehension instead of the loop.

**Why it is better**  
The current loop calls Python-level `np.linalg.norm`, `np.dot`, and `math.acos` once per sample — each is a separate Python → C round-trip. The vectorised version does one C call per operation over all `n` rows, which is ~10–30× faster for typical window sizes (96 samples for a 1.6-hour pass at 60 s steps; far more for a 24-hour window).

`np.einsum("ij,ij->i", A, B)` is the idiomatic batched dot product and is marginally faster than `(A * B).sum(axis=1)` for large `n`.

**Risk / trade-off**  
None. The mathematical identity is exact. No new dependencies. Output values are bit-identical (modulo floating-point associativity for very large `n`, which is negligible).

#### ② Cache the ephemeris at import time

**What changes**  
Lines 185–188 call [`load(str(_EPHEMERIS_PATH))`](Ephemeris/backend/physics/orbit_propagation.py:185) inside `propagate()`. `load()` opens and memory-maps the `.bsp` file every time `propagate()` is called. For a server that handles many requests this is repeated I/O and object allocation for an immutable resource.

Move the loader to module level alongside the existing `_ts` singleton:

```python
# near line 55 — module-level singletons
_ts = load.timescale()
_planets: Any = load(str(_EPHEMERIS_PATH))        # opened once
_earth:   Any = _planets["earth"]                 # constant body reference
```

Then remove lines 185–186 from `propagate()` and replace `earth` / `planets[...]` with the module-level names.

**Why it is better**  
`load()` opens the BSP kernel, reads its segment index, and allocates a Python wrapper — all of which are wasted on every call. Module-level initialisation pays this cost once per process lifetime, which matters both for throughput and for cold-start latency of the first request.

**Risk / trade-off**  
If `_EPHEMERIS_PATH` does not exist at import time the module will raise immediately (instead of only when `propagate()` is first called). This is the preferred behaviour for a service dependency: fail fast at startup rather than silently at request time. If the file could be absent in some deployment, the load should be wrapped in a `try/except` that gives a clear error — but that is a separate concern and the current code does not guard against it either.

#### ③ Build ISO 8601 timestamps in bulk

**What changes**  
The current loop calls `(t0_utc + timedelta(seconds=elapsed_s)).isoformat()` once per point. In Python each `timedelta` construction, `datetime` addition, and `.isoformat()` call is a Python-level object allocation.

A vectorised alternative:

```python
# Build all offsets as a numpy timedelta64 array
offsets_ns = (np.arange(n) * step_s * 1_000_000_000).astype("timedelta64[ns]")
t0_ns      = np.datetime64(t0_utc.replace(tzinfo=None), "ns")   # UTC naive
dt_arr     = t0_ns + offsets_ns                                  # (n,) datetime64[ns]
# Convert to ISO strings with sub-second precision stripped to microseconds
iso_times  = dt_arr.astype("datetime64[us]").astype(str)         # (n,) "<U26"
# Append the UTC suffix that isoformat() adds
iso_times  = np.char.add(iso_times, "+00:00")
```

The result is a NumPy string array that can be indexed directly when building `out`.

**Why it is better**  
Eliminates `n` Python `timedelta` constructions, `n` `datetime.__add__` calls, and `n` `.isoformat()` calls, replacing them with two or three NumPy operations. For a 24-hour window at 10 s steps (`n = 8640`) this is measurable.

**Risk / trade-off**  
`numpy.datetime64` does not store timezone information. The `+00:00` suffix must be appended explicitly (as shown), otherwise consumers that parse the ISO string would get a naïve timestamp. The resulting strings are identical in format to what `datetime.isoformat()` produces for UTC datetimes — verified by the fact that `datetime(2000,1,1,12,0,0,tzinfo=timezone.utc).isoformat()` → `"2000-01-01T12:00:00+00:00"` and `np.datetime64("2000-01-01T12:00:00","us").astype(str)` → `"2000-01-01T12:00:00.000000"` with the suffix appended → `"2000-01-01T12:00:00.000000+00:00"`. The only visible difference is the microseconds field (`.000000`) which is present in the NumPy version when `step_s` is a whole number. If callers are sensitive to this, cast to `datetime64[s]` instead of `[us]` for output identical to the current `isoformat()` output.
