### Case 1 — Granite API unreachable / times out

**Code path:** [`_call_granite()`](Ephemeris/backend/api/explain.py:425) uses `httpx.AsyncClient(timeout=25)`. A timeout raises `httpx.TimeoutException`; unreachable host raises `httpx.ConnectError`. Both are subclasses of `Exception`.

The loop at [line 507–529](Ephemeris/backend/api/explain.py:507):
```python
for attempt in range(2):
    try:
        raw = await _call_granite(...)
        ...
    except Exception:
        break     # ← exits the loop immediately
```

The `break` fires on the **first attempt** (attempt 0), skipping the retry entirely. Execution falls through to [line 531](Ephemeris/backend/api/explain.py:531):
```python
return {**template_explanation(f), "features": asdict(f)}
```

**Result:** ✅ **Graceful.** Returns the full template shape. `source` is `"template"`. However — the exception is silently swallowed with bare `except Exception: break`. The retry on attempt 1 is never reached because `break` exits on *any* exception. That's a minor behavioural gap (network errors could theoretically be retried), but the *response* is clean and the panel is never empty.

### Case 2 — Invalid/expired watsonx credentials

**Code path:** `_call_granite()` calls `r.raise_for_status()` at [line 442](Ephemeris/backend/api/explain.py:442). A 401/403 from watsonx raises `httpx.HTTPStatusError`, which is a subclass of `Exception`. Same `except Exception: break` catches it on the first attempt, falls through to `template_explanation`.

**Result:** ✅ **Graceful.** Same outcome as Case 1 — template returned, `source = "template"`. Same silent-swallow caveat.

**Edge note:** There is also a short-circuit guard at [line 503](Ephemeris/backend/api/explain.py:503):
```python
if not WATSONX_KEY:
    return {**template_explanation(f), "features": asdict(f)}
```
This only fires when the env var is absent entirely. If a key is present but expired, the 401 path applies instead — which still lands on the template, so it's fine.

### Case 3 — Granite returns a malformed/unexpected response shape

Two sub-cases:

**3a — `r.json()["results"][0]["generated_text"]` key access fails** (e.g. response body is `{}` or missing `results`): raises `KeyError` inside `_call_granite`. Caught by `except Exception: break` → template.

**3b — `_parse(raw)` fails** (e.g. Granite returns prose with no JSON braces): [`_parse()`](Ephemeris/backend/api/explain.py:446) explicitly raises `ValueError("no JSON object in model output")` when `start == -1 or end == -1`, or `json.JSONDecodeError` if the braces are there but the content is invalid JSON. Both are caught by `except Exception: break` → template.

**3c — JSON parses fine but fields are missing/wrong type** (e.g. `likely_cause` has an unexpected value): `out.get("likely_cause")` returns `None`, `valid_cause` evaluates `False`, grounding check may also fail. On attempt 0 this triggers the retry with a corrective suffix appended to `user`. On attempt 1, if still invalid, the loop exits naturally (no `break`), and the fallthrough at line 531 returns the template.

**Result:** ✅ **Graceful across all sub-cases.** Template is always the safety net. `source = "template"`.

### Case 4 — Empty or malformed request body to `/explain`

**Code path:** FastAPI + Pydantic validate the request before `explain()` is ever called. [`ExplainRequest`](Ephemeris/backend/api/explain.py:202) has:
- `window: list[AnomalyPoint] = Field(..., min_length=3)` — required, minimum 3 elements
- Each `AnomalyPoint` has strictly typed required fields

On a bad body (missing `window`, wrong types, fewer than 3 points, empty `{}`), Pydantic raises a `RequestValidationError` which FastAPI catches and converts to a **422 Unprocessable Entity** with a structured JSON error body like:
```json
{"detail": [{"loc": [...], "msg": "...", "type": "..."}]}
```

**Result:** ✅ **Graceful** — not a 500, not an unhandled exception. However, this is **not** the template fallback path. It returns a 422 with Pydantic's error detail, not the `{headline, reasoning, ...}` shape. That's the correct and expected behaviour for a genuinely malformed request — the template fallback is for runtime failures when a valid request can't get a live model answer, not for invalid inputs.

### One real issue found: the bare `except Exception: break`

[Line 528–529](Ephemeris/backend/api/explain.py:528):
```python

```

This `break` fires on attempt 0, which means **the retry is unreachable on any exception**. The two-attempt loop effectively becomes one-attempt-plus-fallback for all exception types. The retry was intended for the grounding-validation failure case (which is handled via the `if attempt == 0` branch on lines 521–527 — correctly, without an exception), but a network blip on attempt 0 immediately bails out instead of retrying once.

This doesn't break the Definition of Done — the template still fires and `source = "template"` — but if the intent was to retry on transient errors, the `break` should be `continue`. Worth fixing, but it's not a safety gap.
